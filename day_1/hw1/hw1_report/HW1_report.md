## 1. 개념 정리

### 1-1. 픽셀과 색 표현 방식

이미지는 픽셀이 격자로 모여 만들어지고, 픽셀 하나가 몇 개의 값을 들고 있느냐에 따라 표현 방식이 나뉜다.

| 표현 방식 | 채널 수 | 값의 범위 | 특징 |
|---|---|---|---|
| RGB | 3 | 각 0~255 | 빛의 삼원색으로 색을 정의 |
| Grayscale | 1 | 0~255 | 밝기만 표현, 정보량이 RGB의 1/3 |
| HSV | 3 | H 0~179, S·V 0~255 | 색조·채도·명도로 색을 정의 |
| Binary | 1 | 0 또는 255 | 검은색과 흰색만 |

이번 과제는 "특정 색의 공만 남긴다"가 목적이므로 RGB → HSV → Binary 순서로 흘러간다.

### 1-2. 왜 RGB가 아니라 HSV인가

RGB에서 빨간공을 찾으려면 R값만 크면 된다고 생각하기 쉽지만 실제로는 잘 안 된다. 조명이 밝아지면 R, G, B가 **전부 같이** 올라가고, 그늘이 지면 전부 같이 내려가기 때문이다. 즉 RGB에서는 "색"과 "밝기"가 세 채널에 섞여 있어서 둘을 떼어낼 수가 없다.

HSV는 이 둘을 채널로 분리해 놓은 모델이다.

- **H (Hue, 색조)** — 어떤 색 계열인지. 조명이 밝아져도 거의 그대로다.
- **S (Saturation, 채도)** — 얼마나 선명한 색인지. 회색·흰색·검은색은 S가 낮다.
- **V (Value, 명도)** — 얼마나 밝은지. 조명의 영향을 여기가 대부분 받아준다.

그래서 색 추출은 **H로 색 계열을 고르고, S와 V로 "너무 흐리거나 너무 어두운 것"을 걸러내는** 방식이 된다. 실제로 이번 사진에서도 각 공의 H는 좁은 구간에 몰려 있었지만 V는 반사광 때문에 크게 흩어져 있었다.

### 1-3. inRange와 이진화

`inRange`는 각 픽셀의 세 채널이 모두 지정한 하한~상한 사이에 있으면 255, 아니면 0을 넣어 바이너리 이미지를 만든다.

```cpp
Mat img_hsv;
cvtColor(img, img_hsv, COLOR_BGR2HSV);

Scalar lower = Scalar(h_low, s_low, v_low);
Scalar upper = Scalar(h_high, s_high, v_high);
inRange(img_hsv, lower, upper, mask);
```

여기서 중요한 건 **세 조건이 AND로 묶인다**는 점이다. H가 맞아도 S가 하한보다 낮으면 걸러진다. 그래서 슬라이더를 만질 때 "H는 분명 맞는데 왜 아무것도 안 나오지" 하는 상황은 대부분 S나 V의 하한이 너무 높아서 생긴다.

### 1-4. 가우시안 필터

영상에서 어떤 픽셀이 주변 픽셀과 극단적으로 값이 다르면 그게 노이즈다. 필터는 픽셀을 주변 값과 섞어서 이런 튀는 값을 눌러주는데, 가우시안 필터는 그중에서 **가운데에 가중치를 크게 주고 멀어질수록 작게 주는** 커널을 쓴다.

```
       1  2  1
1/16 × 2  4  2
       1  2  1
```

가중치 합이 1이 되도록 나누기 때문에 전체 밝기는 유지되면서 튀는 값만 완만해진다. 커널이 커질수록(5x5, 9x9 …) 더 넓은 범위를 섞으므로 더 많이 흐려진다.

```cpp
GaussianBlur(src, dst, Size(ksize, ksize), 0);
```

`ksize`는 **홀수**여야 한다. 중심 픽셀이 있어야 하기 때문이다.

## 2. 구현

### 2-1. GUI 구성

| 위젯 | 역할 |
|---|---|
| QLabel 2개 | 왼쪽 원본, 오른쪽 바이너리 |
| QPushButton 3개 (R / G / B) | 추출할 색 선택 |
| QCheckBox + QSlider | 가우시안 ON/OFF, 커널 크기 |
| QSlider 6개 | H·S·V의 하한·상한 직접 조절 |
| QPushButton 3개 | 이미지 열기, 바이너리 저장, 슬라이더 초기화 |

색 버튼을 누르면 그 색의 HSV 기본값이 슬라이더에 자동으로 들어가고, 거기서 슬라이더를 움직여 미세 조정하는 방식으로 만들었다.

### 2-2. 처리 순서

```
원본 → (GaussianBlur) → cvtColor(BGR2HSV) → inRange → 바이너리
```

가우시안 필터는 **cvtColor 앞에** 넣었다. HSV로 바꾼 뒤에 블러를 걸면 Hue 채널까지 섞이는데, Hue는 0과 179가 맞닿은 원형 값이라 빨강(0)과 빨강(179)을 평균 내면 청록(90)이라는 엉뚱한 색이 만들어진다. BGR 상태에서 먼저 흐리게 만든 다음 색 공간을 바꾸는 게 맞다.

### 2-3. 빨간색 Hue 경계 처리

초록과 파랑은 H 구간이 하나로 이어져 있어서 `inRange` 한 번이면 되지만, 빨강은 H가 0 근처와 179 근처 **양 끝**에 걸쳐 있다.

| 색 | Hue 구간 | inRange 호출 |
|---|---|---|
| RED | 170~179, 0~10 | 2회 + OR |
| GREEN | 40~80 | 1회 |
| BLUE | 100~130 | 1회 |

그래서 하한이 상한보다 큰 경우(`h_low > h_high`)를 "0을 넘어가는 구간"으로 해석해서 `inRange`를 두 번 부르고 결과를 OR로 합치도록 했다.

```cpp
if (h_low <= h_high)
{
  inRange(hsv, Scalar(h_low, s_low, v_low), Scalar(h_high, s_high, v_high), mask);
}
else
{
  inRange(hsv, Scalar(0, s_low, v_low), Scalar(h_high, s_high, v_high), mask_low);
  inRange(hsv, Scalar(h_low, s_low, v_low), Scalar(179, s_high, v_high), mask_high);
  mask = mask_low | mask_high;
}
```

### 2-4. HSV 기본값

예제 사진에서 각 공의 픽셀 값을 확인해서 잡은 기본값이다.

| 색 | H | S | V |
|---|---|---|---|
| RED | 170 ~ 10 | 100 ~ 255 | 80 ~ 255 |
| GREEN | 40 ~ 80 | 100 ~ 255 | 80 ~ 255 |
| BLUE | 100 ~ 130 | 100 ~ 255 | 80 ~ 255 |

세 색 모두 S와 V의 하한을 100, 80으로 둔 이유는 책상(연한 나무색, 채도 낮음)과 검은 구조물(명도 낮음)을 한 번에 걸러내기 위해서다.

### 4-2. 무엇이 달라졌는가

**① 작은 노이즈 점이 사라졌다**

가장 크게 바뀐 부분이다. 초록공은 덩어리가 17개에서 2개로, 파란공은 15개에서 1개로 줄어 결국 공 하나만 남았다. 노이즈 점은 주변 픽셀 몇 개가 우연히 그 색 범위에 들어간 것뿐이라 크기가 몇 픽셀밖에 안 되는데, 가우시안 필터를 거치면 주변의 배경 값과 섞이면서 색 범위 밖으로 밀려난다.

**② 공의 윤곽선이 매끄러워졌다**

둘레 값이 줄어든 게 이걸 보여준다. 면적은 거의 그대로인데 둘레만 짧아졌다는 건 경계선의 들쭉날쭉한 계단 모양이 펴졌다는 뜻이다. 필터를 안 걸면 경계에서 픽셀 하나 단위로 색이 급격히 바뀌기 때문에 어떤 픽셀은 범위 안, 바로 옆은 범위 밖이 되면서 지저분한 톱니가 생긴다.

**③ 전체 흰색 픽셀 수는 오히려 조금 늘었다**

처음엔 노이즈가 줄었으니 픽셀 수도 줄 거라고 예상했는데 반대였다. 사라진 노이즈는 다 합쳐도 몇십 픽셀 수준인 데 비해, 경계가 완만해지면서 원래 아슬아슬하게 범위 밖이던 경계 픽셀들이 안으로 들어온 양이 더 많았기 때문이다. 커널을 15x15까지 키우면 공이 번지면서 더 늘어난다.

**④ 반사광 구멍은 그대로 남았다**

구멍 부분의 픽셀 수는 커널을 키워도 거의 변하지 않았다. 반사광은 몇 픽셀짜리 노이즈가 아니라 수백 픽셀 크기의 **실제로 하얀 영역**이라서, 주변과 섞어봐야 여전히 하얗다. 이건 필터로 풀 문제가 아니라 S의 하한을 낮추거나 모폴로지 닫기(close) 연산으로 메워야 하는 부분이다.

### 4-3. 그래서 왜 가우시안 필터를 쓰는가

이진화의 본질은 **연속적인 값에 선을 하나 긋고 넘냐 못 넘냐로 자르는 것**이다. 이렇게 자르는 연산은 경계 근처의 작은 흔들림에 아주 민감하다. 값이 하한 근처에서 오르락내리락하는 픽셀들은 원본의 아주 작은 차이만으로 결과가 0과 255로 완전히 갈라져 버린다.

가우시안 필터는 이진화 **전에** 이 흔들림을 미리 줄여주는 역할을 한다. 정리하면 이유는 세 가지다.

1. **노이즈 제거** — 몇 픽셀짜리 잘못 잡힌 점들이 이진화 단계 전에 걸러진다. 이 점들을 그대로 두면 다음 단계(바운딩박스, 무게중심 계산)에서 결과를 크게 망가뜨린다. 점 하나가 구석에 남아 있으면 바운딩박스가 화면 전체로 커진다.
2. **경계 안정화** — 윤곽선이 매끄러워져서 물체의 모양이 실제에 가까워진다.
3. **결과의 일관성** — 같은 장면을 연속으로 찍어도 센서 노이즈 때문에 프레임마다 결과가 미세하게 달라지는데, 필터를 거치면 프레임 간 차이가 줄어 실시간 처리에서 결과가 덜 떨린다.

### 4-4. 그럼 커널은 클수록 좋은가

아니다. 두 가지 대가가 있다.

**① 물체가 번진다**

15x15에서는 흰색 픽셀 수가 OFF 대비 RED 기준 365픽셀 늘었다. 경계가 실제보다 바깥으로 밀린 것이다. 작은 물체를 찾을 때는 커널이 물체보다 커지면서 물체 자체가 배경에 섞여 사라지기도 한다.

**② 연산 시간이 늘어난다**

640x480 이미지에서 측정한 처리 시간이다.

| 커널 | 시간 |
|---|---|
| 3x3 | 0.182 ms |
| 5x5 | 0.216 ms |
| 9x9 | 0.627 ms |
| 15x15 | 1.102 ms |
| 31x31 | 2.932 ms |

한 장만 처리할 때는 차이가 없어 보이지만 30fps 실시간에서는 매 프레임 드는 비용이다. 이번 사진에서는 **5x5에서 이미 노이즈 덩어리가 대부분 사라졌고 번짐도 크지 않아서**, 5x5가 가장 무난했다.

## 5. 정리

- HSV는 색과 밝기를 분리해 주기 때문에 조명이 일정하지 않은 환경에서 특정 색을 추출할 때 RGB보다 유리하다.
- `inRange`의 세 조건은 AND로 묶이므로, 색이 안 잡힐 때는 H보다 S·V의 하한을 먼저 의심해야 한다.
- 빨강처럼 Hue가 0을 넘어가는 색은 `inRange`를 두 번 불러 OR로 합쳐야 한다.
- 가우시안 필터는 이진화 전에 작은 노이즈와 경계의 흔들림을 줄여, 잘라낸 결과를 깨끗하고 일정하게 만들어 준다.
- 다만 필터가 만능은 아니다. 반사광처럼 넓은 영역의 문제는 HSV 범위 조정이나 모폴로지 연산으로 따로 처리해야 한다.
- 커널 크기는 노이즈 제거 효과와 번짐·연산 시간 사이의 절충이며, 이번 경우엔 5x5가 적절했다.
